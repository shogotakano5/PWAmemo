# メモ — PWA メモアプリ

オフラインでも使えるメモアプリです。メモの保存先を **この端末だけ（ローカル保存）** と
**アカウントを作ってサーバに保存（複数端末で同期）** から選べます。Vercel にそのままデプロイできます。

## できること

- **PWA** — ホーム画面にインストールでき、オフラインでも起動・編集できます（Service Worker + IndexedDB）
- **ローカル保存** — アカウントなしでもすぐ使えます。メモはブラウザの IndexedDB にのみ保存され、外部に送信されません
- **アカウント保存** — メールアドレスをユーザ ID として登録すると、メモが Postgres に保存され複数端末で同期します。
  認証は **パスワード** と **PIN（数字）** から選べます
- **オフライン編集の自動送信** — 圏外で書いた変更は端末に貯まり、オンライン復帰時に自動で送信されます
- **競合解決** — 同じメモを複数端末で編集した場合は更新時刻の新しい方が残ります（last-write-wins）
- **削除の同期** — 削除は tombstone として同期され、他の端末からも消えます
- **ログイン時の取り込み** — ログイン／登録時に、それまで端末に保存していたメモをアカウントへ取り込めます
- **登録データは平文で保存しません** — 詳細は「登録データの保護」を参照
- **管理画面（`/admin`）** — 許可したメールアドレス宛にワンタイムコードを送って管理者としてログインし、
  登録アカウントの一覧確認とアカウント削除ができます。詳細は「管理画面」を参照
- 全文検索、自動保存（入力停止から 0.4 秒）、ダークモード対応、スマホ／デスクトップ両対応のレイアウト

1 行目がそのままメモのタイトルになります。

## 動かす

```bash
npm install
npm run dev          # http://localhost:3000
```

環境変数なしでも動きます。その場合はローカル保存モードのみになり、
ログインボタンからの登録は「サーバ保存は未設定です」と表示されます。

### アカウント機能（サーバ保存）を有効にする

`.env.local` を作って次の 2 つを設定します（`.env.example` を参照）。

| 変数 | 用途 |
| --- | --- |
| `POSTGRES_URL` | Postgres 接続文字列。`DATABASE_URL` でも可 |
| `AUTH_SECRET`  | セッション署名鍵 **兼 暗号化鍵の元**（32 バイト以上推奨） |

> **`AUTH_SECRET` は一度アカウントを作ったら変更しないでください。**
> メールアドレスの暗号化キーと検索用インデックスがこの値から導出されるため、変更すると
> 既存アカウントにログインできなくなります。

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # AUTH_SECRET の生成
```

テーブル（`users` / `memos`）は初回アクセス時に自動作成されるので、マイグレーション操作は不要です。

## Vercel へのデプロイ

1. このリポジトリを GitHub に push し、Vercel で **Import Project**（フレームワークは Next.js が自動検出されます）
2. データベースを用意する
   - Vercel の **Storage → Create Database → Postgres**（Neon）を作成してプロジェクトに接続すると
     `POSTGRES_URL` が自動で環境変数に入ります
   - Supabase など外部の Postgres でも構いません。その場合は `POSTGRES_URL` を手動で登録します
     （`?sslmode=require` を付けてください）
3. **Settings → Environment Variables** で `AUTH_SECRET` を追加する
4. Deploy

アカウント機能を使わず、ローカル保存だけで公開する場合は環境変数の設定は不要です。

補足:

- サーバレス環境では接続数が増えやすいため、プール付きの接続文字列（Neon の `-pooler` ホストなど）を推奨します
- PWA のインストールと Service Worker は HTTPS が必要です。Vercel のドメインはそのまま条件を満たします
  （ローカルでは `localhost` が例外として許可されます）

## 登録データの保護

登録時に受け取る情報（メールアドレスとパスワード／PIN）は、いずれもそのままの形ではデータベースに残りません。

| 項目 | 保存方法 | 理由 |
| --- | --- | --- |
| パスワード / PIN | **scrypt ハッシュ**（ソルト付き、パラメータ込みで保存） | 復号できる暗号化では鍵の漏洩時に元に戻せてしまうため、資格情報は一方向ハッシュが適切です |
| メールアドレス | **AES-256-GCM で暗号化** | 表示のために復号が必要なので、こちらは可逆暗号を使います |
| メールアドレスの照合用 | **HMAC-SHA256 のブラインドインデックス** | GCM の暗号文は毎回変わり検索できないため、重複判定とログイン検索はこの決定的な値で行います。素の SHA-256 ではなく鍵付きなので、テーブルが漏れても既知アドレスの総当たり照合ができません |

実際に `users` テーブルに入る値:

```
id              | ad54151c-a6c6-45ec-98f9-089d8d40d400
email_index     | 6ac8eef4b669fe4d481c1e255984d66b6c0dfdf92e1a9942f1433c0737f6c3a9
email_encrypted | v1$EujtaZg5OmfolIAc$uw9-jbtk52a6OOXbIyWwkxtK$6Tcpk_d7twVTno2H7FE-rA
secret_hash     | scrypt$65536$8$1$…$…
secret_kind     | pin
```

暗号化鍵と HMAC 鍵は `AUTH_SECRET` から HKDF で別々に導出され、Cookie の署名鍵とも別の値になります。

### PIN を選んだ場合

PIN は 4〜10 桁の数字です。短いぶん推測されやすいので、次の対策を入れています。

- 同じ数字の繰り返し（`1111`）と連番（`3456`）は登録できません
- scrypt のコストをパスワードより高く設定しています（N=65536 / パスワードは N=16384）
- **ログインに 5 回連続で失敗するとアカウントをロック**します。ロック時間は失敗が続くほど
  1 分 → 5 分 → 30 分 → 60 分と延びます。成功するとカウンタはリセットされます
- ログイン失敗時のメッセージは「アカウントが存在しない場合」と同一で、登録済みかどうかは分かりません

### 旧バージョンからの移行

メールアドレスを平文で持っていた初期バージョンのテーブルは、初回アクセス時に自動で移行されます
（暗号化列の追加 → 既存行の暗号化 → 平文列の削除）。パラメータを持たない旧形式のパスワード
ハッシュもそのまま検証でき、ログイン成功時に現行パラメータで再ハッシュされます。

## 管理画面

`/admin` から、許可したメールアドレスだけがログインできる簡易管理画面を使えます。パスワードは
持たず、都度メールに送るワンタイムコード（6桁）でログインする方式です。

### 有効にする

`.env.example` の該当箇所を参照し、次を追加で設定してください（`POSTGRES_URL` / `AUTH_SECRET` に加えて必要です）。

| 変数 | 用途 |
| --- | --- |
| `ADMIN_EMAILS` | 管理者として許可するメールアドレス（カンマ区切りで複数可） |
| `SMTP_HOST` / `SMTP_FROM` | ログインコードの送信に使う SMTP サーバと送信元アドレス（必須） |
| `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_SECURE` | 認証が必要な場合や標準以外のポートを使う場合に設定 |

メールボックス、SendGrid・Mailgun・Amazon SES の SMTP リレーなど、SMTP 認証情報を発行できるプロバイダなら
何でも使えます。いずれかが未設定の場合、`/admin` は「未設定です」という案内だけを表示し、機能自体は無効化されます。

### 使い方

1. `/admin` を開き、許可済みのメールアドレスを入力して「コードを送信」
2. 届いたメールの6桁コードを入力してログイン（有効期限10分、5回連続で間違えるとそのコードは失効し再送信が必要）
3. 登録済みアカウントの一覧（メールアドレス／ログイン方法／メモ数／登録日／ロック状態）が表示され、
   行ごとに「削除」でアカウントとそのメモを完全に削除できます（元に戻せません）

管理者はメモアプリの「アカウント」（`users` テーブル）とは別概念です。`ADMIN_EMAILS` に載っているアドレスで
あれば、そのアドレスでメモアプリのアカウントを作っていなくても管理画面にログインできます。未登録のメールアドレスで
コードをリクエストしても、登録済みかどうかが分からないよう常に同じ応答を返し、実際にはメールを送信しません。

## 仕組み

```
ブラウザ                                     サーバ (Next.js Route Handlers)
┌────────────────────────────┐               ┌───────────────────────────────┐
│ React UI                   │               │ /api/auth/signup | login       │
│   ↕                        │               │ /api/auth/logout | me          │
│ IndexedDB (pwa-memo)       │──POST /sync──▶│ /api/memos/sync                │
│   local|…   端末だけのメモ   │◀──変更差分───│   last-write-wins で upsert    │
│   u:<id>|…  アカウントの控え │               │ /api/memos/purge (tombstone GC)│
└────────────────────────────┘               └───────────────┬───────────────┘
        ▲ Service Worker (/sw.js)                            │
        └ アプリシェルをキャッシュ                      Postgres (users, memos)
```

- 書き込みは常にまず IndexedDB に入り、`dirty` フラグが付きます。アカウントモードではその後
  `/api/memos/sync` に送られ、成功したものだけフラグが外れます。だからオフラインでも書けます。
- 同期カーソル（最後に取り込んだ `updatedAt`）を端末ごとに保持し、差分だけをやり取りします。
- パスワード／PIN は scrypt でハッシュ化し、セッションは HMAC-SHA256 で署名した httpOnly Cookie で保持します。

## プライバシー

ローカル保存モードのメモは端末のブラウザから出ません。アカウントモードでは、メモの本文が
自分で用意した Postgres に保存されます。ログアウト時に、この端末へ残っているアカウントの
メモの控えを消すかどうかを選べます。
